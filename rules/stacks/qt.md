# 项目背景
本项目使用 **Qt 5/6** 开发一个桌面应用，涉及图形界面、网络通信和数据存储等功能，目标是提供一个跨平台的桌面应用程序。

# 编码标准
- 所有代码必须符合 **Qt 官方编码规范**（[Qt Coding Style](https://wiki.qt.io/Qt_Coding_Style)）。
- 使用 **4 空格** 进行缩进，禁止使用制表符（Tab）。
- 非成员变量命名使用 **camelCase**，成员变量命名使用**m_camelCase**, 类名使用 **PascalCase**，常量命名使用 **UPPER_SNAKE_CASE**。
- 函数和方法名使用 **camelCase** 风格，避免使用不必要的缩写。
- 所有类和方法必须有适当的文档注释，尤其是涉及复杂逻辑的部分。

# 库和框架约束
- 必须使用 **Qt 5.14** 或 **Qt 6** 版本，不允许使用过时的版本或库。
- 使用 **QML** 进行界面设计，优先采用 **QtQuick** 来实现动态交互。
- 网络通信必须使用 **QtNetwork** 模块，避免使用非 Qt 的第三方库。
- 需要使用 **Qt Widgets** 和 **Qt Quick Controls 2** 结合来构建 UI。

# 文件结构
- 源代码文件应放在 `src/` 目录下，UI 文件应放在 `src/ui/` 目录下。
- 所有资源（如图片、图标等）应放在 `resources/` 目录下，并通过 `.qrc` 文件引用。
- 配置文件应存放在 `config/` 目录下，所有外部库的配置文件应放在 `libs/` 目录下。
- 测试代码应放在 `tests/` 目录下，使用 **QtTest** 框架进行单元测试。

# 文档规范
- 所有类、方法和属性必须使用 **Doxygen** 格式的注释，描述其功能、参数和返回值。
- 对于复杂的 UI 元素和逻辑，必须有详细的说明文档，特别是如何通过 QML 和 C++ 进行交互。
- 配置文件和模块间的交互应该有明确的文档，确保团队成员理解系统架构。

# 安全规范
- 不得在代码中硬编码 **API 密钥** 或 **密码**，应通过环境变量或配置文件传入。
- 所有输入数据应进行有效性检查，避免 **SQL 注入** 和其他安全漏洞。
- 使用 **Qt's QSslSocket** 来进行加密通信，确保数据传输的安全性。
