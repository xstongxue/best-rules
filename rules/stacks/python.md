# 项目背景
本项目使用 **Python 3** 开发一个高效的后端服务，采用 **FastAPI** 框架提供 RESTful API。

# 编码标准
- 所有代码必须符合 **PEP 8** 编码规范。
- 使用 **snake_case** 命名变量和函数，类名使用 **PascalCase**。
- 代码中必须有适当的注释，特别是复杂的逻辑部分，函数必须有 **docstring**。
- 每个文件的行数不得超过 300 行，避免文件过长。

# 库和框架约束
- 使用 **FastAPI** 提供 RESTful API，不得使用其他框架。
- 使用 **SQLAlchemy** 作为 ORM 库，不得使用原生 SQL 查询。
- 使用 **pytest** 进行单元测试，所有代码必须有相应的单元测试覆盖。
- 使用 **black** 格式化代码，禁止手动格式化代码。

# 文件结构
- 所有业务逻辑代码放在 `src/` 目录下。
- API 请求的视图和路由放在 `src/views` 目录下。
- 数据库模型应放在 `src/models` 目录下。
- 所有工具函数应放在 `src/utils` 目录下。

# 文档规范
- 每个模块的顶部应有描述模块功能的注释。
- 每个函数都必须有 **docstring**，包括功能描述、参数说明和返回值类型。
- 代码库的文档应放在 `docs/` 目录下，文档中应详细描述项目架构和 API 使用方法。

# 安全规范
- 绝不将敏感信息（如 **API Keys**、**数据库密码**）硬编码在代码中。
- 所有敏感信息应存储在 `.env` 文件中，并使用 `python-dotenv` 加载。
- 所有输入都必须进行验证，避免 **SQL 注入** 等安全漏洞。
