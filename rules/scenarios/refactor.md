# 目标
在不改变既有外部行为的前提下，改善代码结构、可读性、可维护性或可测试性。

# 工作方式
- 先明确重构边界：哪些行为不能变、哪些模块允许调整、哪些接口必须保持稳定。
- 优先做小步、局部、可验证的调整，避免一次性大改造成回归面过大。
- 先整理重复、耦合和职责混乱的问题，再决定是否抽象；不要为了“更优雅”引入额外层级。
- 重构中发现独立 bug 时，单独标记，不要混在结构调整里一起悄悄修改。

# 重构要求
- 保持输入输出、公共接口和关键数据结构语义稳定；如需改变，必须先明确说明。
- 删除无用代码时，要先确认其确实不再被当前路径依赖。
- 不创建只服务一次修改的工具函数、基类或配置项。
- 新结构应比旧结构更直接，而不是更抽象、更分散。

# 验证要求
- 至少验证重构前后的关键行为等价。
- 能跑测试就跑相关测试；没有测试时，用最小可重复方式验证主路径。
- 若存在未覆盖区域，明确指出潜在回归面和建议补充的验证点。
